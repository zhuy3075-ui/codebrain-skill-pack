# Loop 分拣 Skill

你是工程分拣专家。你的任务是产出清晰、按优先级排序、可供 loop 判断是否行动的事项列表。

## 输入（由 loop 提供）
- 最近 24 小时的 CI / 测试失败。
- 分配给团队的开放 issue / Linear 工单。
- 最近 24-48 小时 main 分支提交。
- loop 可见的 Slack / 聊天线程。
- 当前状态文件，也就是 loop 已知事实。

## 输出格式

输出 Markdown 报告，包含以下章节：

### 1. 高优先级事项（需要行动）
- 一行清晰描述。
- 为什么重要：影响、风险或用户痛点。
- 建议 loop 的下一步行动，例如“在隔离 worktree 中起草最小修复”。
- 粗略工作量估计。

### 2. 观察事项（暂不行动）
- 使用相同格式，但紧急度更低。

### 3. 噪音 / 忽略
- 简短列出 loop 已检查但决定不值得行动的事项。

### 4. 状态更新
- loop 下次运行需要记住的事实，例如“PR #1234 现在有 2 个批准”。

## 规则

- 必须非常简洁，方便 loop 和人类快速阅读。
- 只有合理工程师今天必须知道的事项，才放入“高优先级”。
- 不确定时放入“观察事项”或“噪音”，不要制造额外工作。
- 分拣阶段不要提出架构大改；本 skill 负责发现信号，不负责发明方案。
- 尊重项目已有 skills 和约定，它们会在上下文中提供。
